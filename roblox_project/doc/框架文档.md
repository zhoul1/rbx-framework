# Roblox 工程化开发框架文档

## 概述

本项目采用现代化的 Roblox 外部开发工作流，将代码移出 Studio 编辑器，通过文件系统管理所有脚本，实现 Git 版本控制、团队协作和 AI 辅助开发。

> **核心原则**：
> - **本地写代码 + Rojo 同步** 是日常开发的标准路径，所有 `.luau` 源码存于 `src/` 目录，由 Rojo 实时热推到 Studio。
> - **MCP Full Mode 默认启用**（`boshyxd/robloxstudio-mcp`），供 AI 直接操控 Studio 构建场景、读写实例、执行代码。两者互补，代码改动走 Rojo，3D 场景搭建走 MCP。

## DataModel 映射拓扑

`default.project.json` 定义了本地文件夹与 Studio 服务的对应关系：

| 本地路径 | Studio 位置 | 说明 |
|----------|------------|------|
| `src/server` | `ServerScriptService.Server` | 服务端逻辑，仅服务器访问 |
| `src/client` | `StarterPlayer.StarterPlayerScripts.Client` | 客户端逻辑，玩家加入时加载 |
| `src/shared` | `ReplicatedStorage.Shared` | 双端可访问的共享模块 |
| `Packages` | `ReplicatedStorage.Packages` | Wally 共享包 |

### 文件命名规则

| 文件名模式 | 编译为 Roblox 类型 |
|-----------|-------------------|
| `*.server.luau` | `Script`（服务端脚本） |
| `*.client.luau` | `LocalScript`（客户端脚本） |
| `*.luau` | `ModuleScript`（模块脚本） |
| `init.server.luau` | 文件夹本身变为 `Script` |
| `init.client.luau` | 文件夹本身变为 `LocalScript` |
| `init.luau` | 文件夹本身变为 `ModuleScript` |

> **关键规则**：当使用 `init.server.luau` 时，同目录下的子文件夹会成为该脚本的**子节点**（children），因此代码中应使用 `script:WaitForChild("Services")`，而非 `script.Parent:WaitForChild("Services")`。

## 应用框架：Knit

项目使用 [Knit](https://github.com/sleitnick/Knit) 作为核心应用框架，提供：
- **Service / Controller 单例模式**：自动管理服务端和客户端的模块生命周期
- **网络通信抽象**：自动封装 RemoteEvent / RemoteFunction
- **生命周期钩子**：`KnitInit`（初始化阶段）→ `KnitStart`（所有模块就绪后启动）

### 生命周期顺序

```
服务器启动
  → 加载所有 Services（通过 Knit.AddServices）
  → 触发所有 Service:KnitInit()
  → 触发所有 Service:KnitStart()
  → Knit.Start() Promise 解析完成

客户端加载
  → 加载所有 Controllers（通过 Knit.AddControllers）
  → 触发所有 Controller:KnitInit()
  → 触发所有 Controller:KnitStart()
  → Knit.Start() Promise 解析完成
```

### 创建新 Service（服务端）

在 `src/server/Services/` 下新建 `YourService.luau`：

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Knit = require(ReplicatedStorage.Packages.Knit)

local YourService = Knit.CreateService {
    Name = "YourService",
    Client = {
        -- 客户端可调用的方法定义在这里
    },
}

function YourService:KnitInit()
    -- 初始化阶段：设置内部状态
end

function YourService:KnitStart()
    -- 启动阶段：连接事件，开始逻辑
end

-- 客户端可远程调用的方法
function YourService.Client:GetData(player)
    return "some data"
end

return YourService
```

### 创建新 Controller（客户端）

在 `src/client/Controllers/` 下新建 `YourController.luau`：

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Knit = require(ReplicatedStorage.Packages.Knit)

local YourController = Knit.CreateController {
    Name = "YourController",
}

function YourController:KnitInit()
    -- 初始化阶段
end

function YourController:KnitStart()
    -- 获取服务端服务实例（异步等待连接完成）
    local YourService = Knit.GetService("YourService")
    local data = YourService:GetData()
    print("Got data:", data)
end

return YourController
```

## 日常开发工作流

### 工具职责分工

| 工具 | 职责范围 | 典型场景 |
|------|---------|--------|
| **本地文件 + Rojo** | 所有 Luau 脚本的开发与迭代 | 写 Service / Controller / 共享模块、修 Bug、代码重构 |
| **MCP Full Mode** | Studio DataModel 的直接操控 | 生成关卡场景、创建 Parts、获取树结构、启动/停止测试 |

> **规则**：业务逻辑代码全部写在本地 `src/` 文件夹并通过 Rojo 同步，禁止通过 `execute_luau` 直接注入脚本内容（脚本注入不持久，会被 Rojo 覆盖）。MCP 专用于非脚本的 Studio 操作。

### 每次开发前启动顺序

1. 双击 `start_rojo.bat` → 启动 Rojo 本地同步服务器
2. 打开 Roblox Studio → Rojo 插件点击 **Connect**（本地代码自动同步进 Studio）
3. 确认 MCP 插件已激活（Studio Plugins 面板中 MCP 显示为 Connected 状态）

### 标准开发循环

```
本地 VS Code 编辑 src/ 下的 .luau 文件
      ↓    （文件保存後 Rojo 自动热推）
Studio 实时更新对应脚本内容
      ↓
按 F5 启动 Playtest 验证功能
      ↓
若需要 AI 辅助 → Antigravity 通过 MCP Full Mode 直接读取/操控 Studio
      ↓
功能完成 → git add + git commit 提交到对应 feature 分支
```

### 代码规范检查

```bash
# Lint 检查（静态分析）
selene src/

# 格式化检查（CI 用）
stylua --check src/

# 自动格式化代码
stylua src/
```

## MCP Full Mode（AI 直接操控 Studio）

通过 Antigravity + 社区 MCP 插件（`boshyxd/robloxstudio-mcp`），AI 可直接在 Studio 中执行 Luau 代码、创建实例、读取脚本内容等，共计 65+ 个工具。

### 配置文件

位置：`C:\Users\<用户名>\.gemini\antigravity\mcp_config.json`

```json
{
  "mcpServers": {
    "robloxstudio_community": {
      "command": "npx",
      "args": ["-y", "robloxstudio-mcp@latest"]
    }
  }
}
```

### Studio 插件位置

`C:\Users\<用户名>\AppData\Local\Roblox\Plugins\MCPPlugin.rbxmx`

### 前置要求

在 Studio 中开启：`Home` → `Game Settings` → `Security` → **Allow HTTP Requests** ✅

## 安全原则

> 来自 Roblox 黄金法则：**永远不要信任客户端。** 所有 RemoteEvent 的数据都是攻击者可控的，必须在服务端对类型、范围、所有权和冷却时间进行校验。

| 风险 | 防护措施 |
|------|---------|
| DataStore 数据损坏 | 使用 ProfileService（会话锁机制） |
| 客户端货币作弊 | 所有货币计算在服务端执行，客户端仅展示 |
| RemoteEvent 洪泛 | 在服务器端对每个玩家实现速率限制 |
| 内存泄漏 | 使用 Trove 管理所有 `:Connect()` 连接 |
